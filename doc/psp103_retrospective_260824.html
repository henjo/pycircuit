02

What the model is

A PSP103 core — surface potential solved in closed form, not a threshold-voltage model — expressed as a symbolic expression tree and compiled, with its Jacobian, by automatic differentiation. It reads a real 359-parameter foundry card through a geometry-scaling layer that reimplements the vendor's own scaling, and it is compared against curves generated by the vendor's compiled binary.

What it now contains: the intrinsic current and charge, geometry and temperature scaling, series resistance, velocity saturation, channel-length modulation, DIBL, polysilicon depletion, quantum-mechanical oxide correction, overlap and fringe capacitance, JUNCAP2 junctions with reverse leakage, channel thermal and flicker noise, induced gate noise with its drain correlation, impact ionisation, and gate tunnelling.

Two properties are structural rather than checked: charge conservation and exact source/drain antisymmetry both follow from how the contributions are wired, not from an identity that has to hold numerically. That is what made the leakage terms interesting — they are the first physics in the model that legitimately breaks the antisymmetry, because they take current out of the channel and into a third terminal.
03

How the model is generated

Nothing here is hand-differentiated. The element is written as contribution statements — the DSL's form of Verilog-A's I(a,b) <+ expr — inside an analog() method whose arguments name the terminals. A metaclass compiles those equations symbolically into everything a simulator needs: the current and charge vectors, and their exact closed-form Jacobians.

writtenContributions

One expression per branch. Terminal voltages are symbols; ddt() marks a charge.

compiledExpression tree

Each additive term routes by kind — ddt to q, circuit-free terms to u(t), the rest to i.

differentiatedExact Jacobians

G = ∂i/∂x and C = ∂q/∂x as symbolic Jacobians — no finite differences, no chain rule by hand.

emittedCallable stamps

Lambdified with common-subexpression elimination, against NumPy or JAX.

The same set of ideas every equation-defined device compiler uses — Qucs EDD, Xyce ABM, ngspice B-sources — done with a computer-algebra system so the Jacobians are exact rather than approximated.

A complete element 
class Diode(Behavioural):
    terminals = ('plus', 'minus')
    instparams = [Parameter(name='isat', default=1e-15),
                  Parameter(name='tau',  default=1e-12)]

    def analog(plus, minus):
        br = Branch(plus, minus)
        i = var(isat * (sympy.exp(br.V / 0.025852) - 1.0), 'id')
        return (Contribution(br.I, i),
                Contribution(br.I, ddt(tau * i)))

Twelve lines of physics; the residual, the exact conductance matrix and the charge vector are generated. The MOSFET is the same mechanism with a surface-potential solve inside it — 1,671 lines of kernel producing a chain of some 700 intermediates.

Two things this changes

The derivative is a different program from the value. It is generated, it is larger, and it divides by things the value never divides by. A model can be finite everywhere and have a NaN Jacobian at one bias — the worse failure, because nothing looks wrong and the solver is silently poisoned.

Both arms of every conditional are evaluated. A compiled conditional becomes a where, which selects afterwards. The discarded arm still overflows and still contributes its NaN to anything combining the two, so each arm's input must be clamped to that arm's own domain. Three overflows in the last block written here were of exactly this kind.

The practical consequence is that var() is arithmetic, not optimisation: naming an intermediate fixes the order of operations, and bare sub-expressions get substituted into one another and multiplied out before printing. The same algebra typed into a REPL can return a finite number where the compiled chain returns NaN.

04

Using it

The element takes scaled parameters, not a card. The scaling layer reimplements the vendor's own geometry and temperature scaling, so one card and a (W, L, T) gives the ~60 values the element needs — and every one of them has been checked term by term against the vendor's own reported values at four geometries on both channel types.

# 1. read the foundry card and scale it for one geometry
deck = spicecard.read(PDK + '/cornerMOSlv.lib', section='mos_tt')
card = deck.model_params('sg13g2_lv_nmos_psp', w=1e-6, l=0.13e-6,
                         ng=1, m=1, pre_layout=1)
kw   = psp_scaling.to_long_channel(card, w=1e-6, l=0.13e-6, T=300.15)

# 2. build a circuit around it  (d, g, s, b)
c = SubCircuit()
d, g = c.add_node('d'), c.add_node('g')
c['Vd'] = VS(d, gnd, v=1.2)
c['Vg'] = VS(g, gnd, v=0.0)
c['M1'] = PspMosLongChannel(d, g, gnd, gnd, **kw)

# 3. sweep the gate and read the drain current
res = DCSweep(c).solve('Vg', 'v', np.linspace(0.4, 1.2, 5))

What you get, and what you should know

  • Four terminals — d, g, s, b — plus internal nodes for gate resistance and the induced-gate-noise network, which collapse away when their parameters are zero.
  • DC, AC, noise and transient, on the NumPy toolkit or the JAX one; the batched path evaluates many parameter sets at once and is worth 22× at 512 lanes.
  • Both channel types — PspMosLongChannel and PspPmosLongChannel. The card carries the polarity; the classes differ only where the physics genuinely does.
  • The p-channel card is a different card, not mirrored numbers. Four terms were found here only because a coefficient that is zero on one card is alive on the other.
  • It is not PSP103 and should not be substituted for it in design work. It is PSP103's core, built to establish that the DSL can carry a surface-potential formulation, and measured so that the claim has a number attached.

One shape, five times

The five hardest bugs were all the same shape, and it is a shape that reading the source cannot see, because every term that is present is transcribed correctly. In each case the reference computes a quantity in one place and uses it somewhere the transcription did not follow.

One name, two quantities

PSP's Vdsx is Vds²/(√(Vds²+0.01)+0.1) — a softened drain bias, quadratic near the origin. The element separately needs a smooth |Vds|, because ordering the terminals with a branch is something a single compiled expression cannot do. Two different quantities; one suggestive name.

5.5% of the weak-inversion current, and at Vds = 0.05 the two differ by a factor of four.

One term, present at one site

The mobility is evaluated at the channel midpoint and again at the source end. The series-resistance contribution appears in both. Ours had it in the midpoint only.

26% of the source-end mobility, which propagated into the saturation voltage.

One quantity, used at two sites

The conditioned source bias Vsb* feeds both the quasi-Fermi level and the gate drive. We had it in the first.

331 µV at Vsb = 1 — and 9.9 µV at Vsb = 0, which is why the zero-body sweeps were never quite exact either.

One name, reassigned in place

PSP corrects the midpoint surface potential for polysilicon depletion by writing x_m = x_m + u_pd. Every line after that sees the corrected value. We computed the correction, used it for the charges and the current, and handed the raw midpoint to a third consumer.

0.7 mV of surface potential — nothing in the drain current, 7% of the gate current, because that one is an exponential of it.

One constant, two scales

A smoothing width written as an absolute 1e-3, divided by a scaled parameter that is 0.322 on one card and 7.38×10⁻⁶ on the other. The same constant was 0.3% of one scale and 135× the other.

2.5×10⁻⁴, entirely on the p-channel, and invisible on the card it was tuned against.

07

The methods

Ordered roughly by cost. Each is cheap relative to the one after it, and each earned its place by finding something here.

Be wrong against something external

A model checked only against itself is checked for consistency, not correctness. A charge model here passed exact conservation, exact source/drain symmetry and an unfitted Ward–Dutton partition — and was 24% wrong. Every one of those checks is a ratio, and a uniform error in the oxide capacitance divides out of all of them.

What works instead: a quantity the reference exports. PSP publishes its scaled parameters as operating-point outputs; comparing them term by term turns "is the scaling right?" from an inference about currents into a direct check. A current can be right for compensating reasons — a parameter cannot.

Read the spread before the median

The median ratio says whether the gain is right. The spread across a sweep says whether the bias dependence is — and that is what the physics governs and what a missing term breaks.

Two correct blocks were switched off here for making the median worse. Judged by spread they were worth 1.80 → 0.38, and the decision was reversed.

Convert to the unit the error lives in

A current ratio in an exponential regime is a voltage. Dividing by the local d ln I / dVg says both how large the discrepancy is in millivolts and — from whether the result is flat — whether it is an offset at all.

A residual that read as a bias-dependent mess became a flat 0.35 mV, which is one cause with one number, and the cause followed within the hour.

Bound, don't fit

Turn each suspect off, one at a time, and see how far the number moves. Read the eliminations as hard as the hits: a term whose removal changes nothing is out; a term whose removal breaks something currently exact is right.

Leverage is not error. The strongest false lead here had four independent arguments — right regime, 0.98 shape correlation, right leverage, and a coefficient non-zero on one card and exactly zero on the other. All four were wrong.

The differential over the shared input

Modify the model card so a term is disabled, and let both implementations read the modified file. If the disagreement vanishes, the discrepancy is in that term — causally, without reading a line.

Fourteen candidates left a residual at exactly 100% of baseline; zeroing one block collapsed it to 5.3×10⁻⁷. Arithmetic on the sub-terms then localised it to a single logarithm with no further runs.

Strobe the reference's own internals

When the differential says a term is wrong and every ingredient still matches, the mechanism is invisible to reading. Add debug outputs to a copy of the reference source, rebuild, run one bias point. Strobe a whole chain at once — the ratios then localise the error themselves.

Three bugs were found this way after repeated term-by-term readings found nothing, each in a single run. The last: six quantities matched to seven digits, one did not, and the discrepancy in the final answer equalled the discrepancy in that one exactly.

Dump your own compiled chain

Take the generated source, re-execute it with a capture after every assignment, and find the first non-finite variable. That turns "somewhere in two thousand lines" into one name.

Located three separate overflows in new code, each of which reported as a plausible physical failure at the terminals.

Know where the reference's floor is

Reference curves have floors — leakage, printed precision, and the solver's own convergence. Measuring below one measures its floor.

The golden data was converged to 10⁻³ while being compared at 10⁻⁴, and it did not look like noise: point-to-point error reads as a kink at one bias, which invites a search for a mechanism. It cost two false leads before it was measured.

Record every terminal, not just the interesting one

Reference data is terminal current, which includes every path to that terminal. When the other terminals are not negligible they stop being contamination and become the best instrument available: they name what is missing.

Two residuals were identified outright with no differential and nothing fitted — ours + |ib| reproduced the vendor at 0.9999994 flat across a sweep, and a second was −0.49 × ig constant across its window.

08

Where the method failed

Six wrong turns, each of which produced a confident answer before it produced a correct one. These are the entries worth re-reading; the successes above are mostly the same few techniques applied patiently.

A tidy answer is not a correct one

A measurement window reaching below the reference's 2 pA leakage floor produced a clean, flat 0.5% that read exactly like a thermal-voltage error. The clean window gave 0.01%. The most dangerous result is the one that looks like an explanation.

Three positions on one point

A term with the right shape and enough leverage was called the cause, then corrected to correlation, then shown by differential to have been the cause after all. The middle position was the only honest one at the time — leverage had not yet been separated from error.

A confounded experiment, published

Sweeping one solver tolerance over eight decades showed no change, so it was declared irrelevant. It changed nothing because the other tolerance was already tight in every run of that sweep — and the sweep covered one kind of analysis, the one where the other knob happens to suffice. The wrong conclusion reached a deck comment, a documentation section, two test docstrings and a skill file before an untested case contradicted it.

Zero is not an off switch

The element compiles from symbolic parameters, so a block guarded by if param != 0 is built whatever the value; passing zero only multiplies the result by zero at the end, and 0 × ∞ = NaN. Setting a coefficient to zero and watching a failure persist was taken as proof the block was innocent. It was the cause. The valid control is a build without the code.

An exit code is not evidence

The simulator exits 0 on a missing model binary. A successful return was read as a successful rebuild, and an hour went into bisecting a patch that was never the problem. Assert on the output, not the status.

A stale note is worse than no note

A test named ..._terms_are_absent pointed the next investigator at two terms that had been implemented weeks earlier; its body only ever asserted something unrelated and true. It worked exactly as designed, on a residual it had nothing to do with. A signpost is trusted like a measurement and is not one.

09

What holds it

The comparison is guarded by 144 tests in 29 classes, and the discipline that matters is not their number. A tolerance is only a regression guard if it fails on the code you just fixed: after each fix here, the band was reverted against and checked to bite. One band was tightened three times in a single session, from 3% to 0.001 to 5×10⁻⁵, because each fix made the previous bound decorative.

A recorded trade-off has a shelf life. Two of the last four bugs were documented, measured, and deliberately left — correctly, at the time, because the error was negligible against a model 1.6% out. Both became the largest remaining term once everything else reached 3×10⁻⁵, and nothing announced it: a passing test that pins a bounded error goes on passing. After any large accuracy gain, re-read the recorded known-gaps and ask which is now the biggest thing left.

Three skill files carry the transferable part — on finding numerical discrepancies against a reference, on designing comparisons that can fail, and on numerics for code that is symbolically differentiated. They contain only measurements from this work, not general advice.
